## The lines

  d_det = d*, envelope = L*)`, run as `[.conda-unidrive-linux/bin/python, -B, framelease_v4/arms/run_closed_loop_v4.py,
  --arm fl_behaviour, --fast-prefix sdpa,gpu_preproc,lora_merged, --kappa, --seed 11, --routes, --route-id, --port,
  --output-dir, --timeout-s 1410, --lock-wait-s 600, --policy-params {"utility": ...}, --envelope L*]`.
* Behaviour seed (Sec. 2.6): `collection_plan.behaviour_seed(route, kappa, rep 0)`; the utility name records the seed
  and, for d* < 10, the base depth.
* Ids: `v4p2_fl_behaviour_<L*>_eps0.300_d<d*>_k<kappa>_s11_r<route>`. Tier 2, wall cap 1500 s.
* Output directories: `outputs/framelease_v4/rl_data/k1.0`, `k1.5`, `k2.0` (Sec. 8.6; runs in `<dir>/runs/`).
* Order (Sec. 8.2, with the kappas in the place of the arms): the id-sorted routes shuffled with

* Pins: `framelease_v4/arms/jobs_v4.code_pins([L*])`: the 49 code files the P1 lines pin (Sec. 8.3) plus the envelope

**Not registered; entered in Sec. 13.2 with the job file** (GAP_AUDIT Sec. 6, item 5(d)): the block number 10 (the

### 1. Generate and validate the job file (CPU only)

```
source linux/env.sh && CUDA_VISIBLE_DEVICES= OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
    nice -n 19 ionice -c 3 .conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/p2_jobs.py --check --write
```

`CUDA_VISIBLE_DEVICES=` comes after `source linux/env.sh`: `linux/env.sh` sets `${CUDA_VISIBLE_DEVICES:-0}`, which
turns an empty value set before it into 0. `--check` validates every line before anything is written:
* gpu_queue's contract and the pins (against the tree and against `jobs_v4.code_pins([L*])`);
* training routes only, the behaviour seed rule, L*, ids, ports, output directories, the 132 cells and the kappa
  balance of every prefix;
* the launcher's parsing, configuration build and preflight in this process, against each line's kappa;
* the exact command with `--dry-run` in a subprocess, with at most 2 workers.

Exit codes:
* 0: written; prints the paths and sha256 of the job file, the stage spec and the check.
* 1: a check failed; nothing is written.
* 2: refused, nothing is written. Causes: no freeze, a freeze not cited in Sec. 13.2, an unsealed PROTOCOL.md, a test
  route, existing P2 runs (also with `--force`), a queue path, an existing file with other content (`--force` only
  before any P2 run exists).

With unchanged inputs (the freeze, PROTOCOL.md, the pinned tree), a second run writes the same bytes. Once the entry of
step 2 has changed PROTOCOL.md, a second run refuses to rewrite the recorded files: the stage spec records the
PROTOCOL.md sha256.

### 2. Record the job file in PROTOCOL Sec. 13.2 (before the launch)

Under the protocol lock, as every other editor of PROTOCOL.md (`flock framelease_v4/.protocol.lock -c '<entry;
re-seal>'`), append a dated entry to Sec. 13.2. It holds:
* the paths and sha256 of `b10_rl_data.jsonl`, `.stage.json` and `.check.json`, and the 132 lines;
* the block number 10, the route-order seed 20261120 and the queue `outputs/framelease_v4/queue_p2`;
* L* and d* as in the freeze.

Re-seal as for every entry: if files under `framelease_v4/` changed since the last seal, first run
`registration.py --write-manifest --force`; the entry then cites the new manifest sha256. Then run
`registration.py --seal` and `registration.py --verify`. The P2 files are outside the registration manifest's globs:
the sha256 in the entry are their record (GAP_AUDIT G-3).

### 3. Enqueue and launch

```
sha256sum outputs/framelease_v4/p2_jobs/FULL/b10_rl_data.jsonl            # = the sha256 in the Sec. 13.2 entry
mkdir -p outputs/framelease_v4/queue_p2/jobs.d
cp outputs/framelease_v4/p2_jobs/FULL/b10_rl_data.jsonl outputs/framelease_v4/queue_p2/jobs.d/
bash framelease_v4/protocol/launch_queue.sh outputs/framelease_v4/queue_p2 --dry-run   # checks, starts nothing
bash framelease_v4/protocol/launch_queue.sh outputs/framelease_v4/queue_p2
```

`launch_queue.sh` sources `linux/env.sh` itself. It refuses to start while `queue_p2/STOP` exists or another runner
holds the queue. It starts the unchanged runner (`framelease_v2/gpu_queue.py --exit-when-empty --min-free-gib 6`, log
`queue_p2/runner.nohup.log`) with the disk watchdog (`STOP` below 5 GiB free, log `queue_p2/disk_watchdog.log`).

### 4. Autoresume

```
echo outputs/framelease_v4/queue_p2 >> outputs/framelease_v4/AUTORESUME
```

`AUTORESUME` lists queue directories, one per line (`framelease_v4/protocol/autoresume.sh`). It acts only while the
file exists and only if the user installed the `@reboot` crontab line (Sec. 13.2, operational addition). Creating the
file enables autoresume for every listed queue, which is the user's decision. A listed queue with nothing pending is
skipped.

### 6. Completion check and data manifest (after the runner exited)

```
OMP_NUM_THREADS=1 nice -n 19 ionice -c 3 .conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/p2_check.py \
    --queue outputs/framelease_v4/queue_p2 --write
```

The episode of a job is the run of the runner's final record in `queue_p2/status.jsonl`, never a directory listing.
Failed and uncounted attempts stay in `rl_data/k*/runs/` and are listed as excluded runs. Per episode the check
covers the official record, the configuration and pins, the V4Runtime summary, the fast prefix, complete decision rows,
the behaviour logging (`v4_mu`, `v4_explore`, `v4_base_action`, `v4_draw`) and the source logs (with their sha256).

Exit codes:
* 0 PASS: writes `outputs/framelease_v4/rl_data/data_manifest.json` and `p2_check.json`.
  * Enter both paths and sha256 in PROTOCOL Sec. 13.2. The manifest is the dataset manifest of the RL freeze (Sec.
    5.9), and P3 builds the dataset from exactly its episodes.
  * Jobs without a valid record after the single infrastructure retry are listed as missing episodes with their cause.
    They are not re-run beyond the registered retry and nothing is imputed (Secs. 8.4, 9.8; GAP_AUDIT Sec. 6,
    item 5(c), the user's decision).
* 1 FAIL: no manifest; investigate before P3. Causes: a runner `ok` without a matching valid run, an episode that
  fails a criterion, or a queue copy of the job file that differs from it.
* 3 INCOMPLETE: a job is not final yet.
* 2 error: missing inputs, or a test route.

An existing report or manifest is never overwritten with other content without `--force`. An equal one is kept, so a
cited sha256 stays valid.

### Control

* `touch outputs/framelease_v4/queue_p2/STOP` ends the runner after the running job; `PAUSE` holds new starts.
* If the disk watchdog placed `STOP`: free space, check `df`, remove `STOP` by hand, then relaunch.
* The P2 lines pin the same 49 files as the P1 lines, plus L*. Any edit of a pinned file makes the runner block these
  lines (logged BLOCKED). Restore the file, or amend the protocol and regenerate the job file with
  `--check --write --force` before any P2 run exists. `p2_jobs.py` refuses to write once `rl_data/k*/runs/` holds a run.
