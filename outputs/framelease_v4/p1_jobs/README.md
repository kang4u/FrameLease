## Exact commands (to be run by the user; nothing below has been run)

Every command runs from the project root, `cd /home/kang/Desktop/DAC`. P1-0 and P1 share the queue directory
`outputs/framelease_v4/queue_p1`. `launch_queue.sh` sources `linux/env.sh` itself, refuses to start while
`queue_p1/STOP` exists or another runner holds the queue, and starts the unchanged runner
(`framelease_v2/gpu_queue.py --exit-when-empty --min-free-gib 6`, log `queue_p1/runner.nohup.log`) together with the
disk watchdog (`STOP` below 5 GiB free, log `queue_p1/disk_watchdog.log`).

```

    outputs/framelease_v4/registration/MANIFEST.sha256 | sha256sum -c  # the registered job files are unchanged
df -h /home/kang/Desktop/DAC                                           # FULL needs >= 15.8 GiB free (P1-0 alone 6.1 GiB)
```

### 1. P1-0 smoke (7 runs, about 0.9 GPU-h)


Monitoring (read-only):
`.conda-unidrive-linux/bin/python -I -B framelease_v2/gpu_queue.py --queue-dir outputs/framelease_v4/queue_p1 --list`
and `tail -f outputs/framelease_v4/queue_p1/runner.log`. The runner exits when the 7 jobs are final; the watchdog
exits with it.

### 2. Smoke check (after the runner exited)

```
.conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/check_smoke.py --queue outputs/framelease_v4/queue_p1 --write
```

Exit code 0 = PASS: enter the printed report path and sha256 (`outputs/framelease_v4/smoke_p1_0/smoke_check.json`) in
PROTOCOL Sec. 13.2, then continue. 1 = FAIL: stop; the cause is fixed and the smoke block is run again (a change of a
pinned file or a criterion is an amendment, and the job file is regenerated). 3 = INCOMPLETE: a job is not final yet.
Items listed as "deferred to the first P2 run" do not block P1.

### 4. Every later stage (after the runs of the stage it depends on are final)

Dependency order: `lease_s1` -> `lease_s2` -> `heur_s1` -> `heur_s2` -> `age_s1` -> `age_s2`, and `event_s1` ->
`event_s2`. For example, after `lease_s1`:

```
.conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/select_stage.py --variant FULL --stage lease_s1 \
    --queue outputs/framelease_v4/queue_p1 --write
source linux/env.sh && CUDA_VISIBLE_DEVICES= .conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/p1_jobs.py \
    --variant FULL --block lease_s2 --check --write
cp outputs/framelease_v4/p1_jobs/FULL/b04_lease_s2.jsonl outputs/framelease_v4/queue_p1/jobs.d/
bash framelease_v4/protocol/launch_queue.sh outputs/framelease_v4/queue_p1    # only if the runner has exited
```

`select_stage.py` exit codes: 0 written; 3 jobs not final yet (wait); 2 error (message; e.g. a runner `ok` without a
matching run directory). A `FLAG` line (repeated agent set-up failures of a candidate) is investigated before the next
block is generated. Each selection's sha256 (printed) is entered in PROTOCOL Sec. 13 before the next job file is
generated. A running runner picks up new job files by itself.

### 5. Tuning freeze and D1

```
.conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/select_stage.py --variant FULL --freeze --write
.conda-unidrive-linux/bin/python -I -B framelease_v4/protocol/d1_summary.py --variant FULL \
    --queue outputs/framelease_v4/queue_p1 --write
```

The freeze's sha256 goes into PROTOCOL Sec. 13.2; the D1 summary (`outputs/framelease_v4/tuning/d1/`) goes to the
user, who decides on D1.

### Control

`touch outputs/framelease_v4/queue_p1/STOP` ends the runner after the running job; `PAUSE` holds new starts. If the
disk watchdog placed `STOP`: free space, check `df`, remove `STOP` by hand, relaunch. Any edit of a pinned source (v4
arms, `framelease_v4/rl/{__init__,behaviour,features,qnet}.py`, the envelope files) makes the runner block these lines
(logged BLOCKED): restore the file, or amend the protocol and regenerate the job files with `--check --write --force`
before any run of them exists.
